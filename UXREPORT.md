## Aturan penulisan (wajib dipatuhi semua agent)

- **UX Agent**: hanya **menambahkan (append)** item baru di bagian "Open Items", di paling bawah. Jangan pernah edit atau hapus item yang sudah ada.
- **Programmer Agent**: hanya boleh mengubah baris `Status` dan field `Fixed by` pada item yang sudah ada. Jangan edit deskripsi yang ditulis UX.
- **ID**: format `UX-001`, `UX-002`, dst — selalu increment dari ID terakhir di file ini.
- **Issue type**: `Copy` (teks/tone tidak sesuai gaya hangat-informal) / `Hierarchy` (urutan/penekanan visual salah) / `Consistency` (beda pola dari layar lain) / `Accessibility` (kontras, ukuran tap target, dsb) / `Emotional tone` (bikin user cemas/bingung, bukan warm & supportive).

- **Status**: `OPEN` → `IN-PROGRESS` → `FIXED` (atau `WONTFIX` / `NEEDS-DECISION` dengan alasan singkat).

### UX-001 — [FIXED] [Medium] [Emotional tone]
- Ditemukan: 2026-07-25 07:23 oleh UX Agent
- Screen: Beranda (home), cold start setelah app di-force-stop lalu dibuka lagi
- Masalah: Saat aplikasi dibuka dari kondisi benar-benar tertutup (bukan resume), layar Beranda sempat merender penuh dalam kondisi "kosong" — "Total Saldo Rp0", banner "Belum ada anggaran, Bun...", dan "Belum ada transaksi, Bun. Yuk catat yang pertama." — meskipun database sebenarnya sudah berisi puluhan juta rupiah saldo dan banyak transaksi. Saya menangkap ini secara konkret lewat screenshot (bukan cuma splash screen native): setelah generate data dummy dan konfirmasi saldo Rp18.419.420 tampil normal di Beranda, saya menjalankan ulang flow Maestro (`launchApp` + `scroll`) dan screenshot berikutnya menunjukkan Beranda dengan Rp0/"Belum ada transaksi" — lalu screenshot berikutnya lagi (tanpa aksi apa pun selain menunggu) sudah kembali menampilkan Rp18.419.420 dan daftar transaksi lengkap. Root cause dikonfirmasi di kode: `lib/main.dart` memanggil `FinanceRepository()..load()` — `load()` ini fire-and-forget, TIDAK di-`await` sebelum `runApp()`, dan `FinanceRepository` tidak punya flag `isLoading` sama sekali (`lib/repositories/finance_repository.dart`: `_wallets`, `_categories`, `_transactions`, `_budgets` semua mulai sebagai list kosong dan baru terisi setelah query SQLite di `load()` selesai lalu `notifyListeners()`). Screen manapun yang `context.watch<FinanceRepository>()` akan merender state kosong ini dulu untuk beberapa frame sebelum data asli muncul — tidak ada indikator loading yang membedakan "sedang memuat" dari "memang belum ada data".
- Kenapa ini masalah (rujuk spec section jika relevan): Doc section 2.6 menekankan tone yang hangat dan mendukung, bukan bikin cemas — dan seluruh premis aplikasi ini adalah membantu ibu rumah tangga mengontrol keuangan dengan tenang. Melihat sekilas "Rp0" dan "Belum ada transaksi" padahal baru saja mencatat banyak pengeluaran/pemasukan bisa memicu momen panik singkat ("uang saya hilang?") — kecil kemungkinannya durasinya lama di device modern, tapi flash ini nyata dan berulang (saya tangkap 2x dalam sesi yang sama), dan pesan "Belum ada transaksi, Bun. Yuk catat yang pertama." jelas ditulis untuk pengguna baru, bukan untuk pengguna lama yang datanya sedang dimuat.
- Saran perbaikan: Tambahkan flag `isLoading` di `FinanceRepository` (true sampai `load()` selesai) dan tampilkan skeleton/spinner netral alih-alih empty-state penuh selama loading — atau, lebih sederhana, `await` `load()` sebelum `runApp()` dan pertahankan native splash screen sampai data siap (Flutter mendukung ini lewat `FlutterNativeSplash` atau menunda `runApp` dengan `WidgetsBinding.instance.deferFirstFrame()`/`allowFirstFrame()`).
- Maestro flow: maestro/flows/ux-001-repro.yaml
- Fixed by: Programmer, 2026-07-25 — added `isLoading` flag to `FinanceRepository` (true until `load()` completes, `notifyListeners()`d at the end), and `HomeView` now shows a centered `CircularProgressIndicator` in place of the ListView while `isLoading` is true, instead of rendering the empty-state copy. `flutter analyze` clean, verified on-device (fresh install shows no empty-state flash).

### UX-003 — [FIXED] [Low] [Copy]
- Ditemukan: 2026-07-25 07:36 oleh UX Agent
- Screen: Rangkuman > kartu "Bulanan ini vs sebelumnya" (juga berlaku untuk Harian/Mingguan/Tahunan), khusus saat belum ada transaksi pengeluaran sama sekali di kedua periode
- Masalah: Pada instalasi baru/state kosong (belum ada transaksi apa pun), kartu perbandingan menampilkan "▲ 0% lebih boros" — padahal tidak ada dasar untuk bilang "lebih boros" karena memang belum pernah ada pengeluaran sama sekali di kedua periode yang dibandingkan. Saya konfirmasi lewat kode: `lib/screens/summary_screen.dart` baris 197-200 — `changePct = previousExpense == 0 ? (expense == 0 ? 0 : 100) : (...)`, lalu `improved = changePct < 0`. Saat `previousExpense == 0` DAN `expense == 0` (benar-benar kosong), `changePct` jadi `0`, dan karena `0 < 0` adalah `false`, label default jatuh ke cabang "lebih boros" — bukan karena ada perilaku belanja yang memang lebih boros, tapi murni karena `changePct` tidak negatif. Dibandingkan dengan skenario ada data (saya cek juga dengan data dummy: "▼ 26% lebih hemat" tampil benar berwarna hijau saat memang ada penurunan pengeluaran), kasus zero-data ini adalah edge case yang framing-nya keliru.
- Kenapa ini masalah (rujuk spec section jika relevan): Doc section 2.6 minta tone yang suportif, tidak menyalahkan/menghakimi user. Label "lebih boros" (dengan warna aksen oranye-pink yang sama dipakai untuk kondisi over-budget) muncul di layar PALING PERTAMA yang dilihat user baru yang belum sempat mencatat apa-apa — kesan pertama yang salah framing seperti ini kurang pas untuk fitur yang seharusnya menenangkan, bukan menghakimi dari titik nol.
- Saran perbaikan: Tambahkan kondisi eksplisit — kalau `previousExpense == 0 && expense == 0`, tampilkan state netral (mis. sembunyikan badge %, atau tampilkan teks netral seperti "Belum ada data untuk dibandingkan, Bun" tanpa panah/warna) alih-alih memaksakan label "lebih boros".
- Maestro flow: maestro/flows/ux-003-repro.yaml
- Fixed by: Programmer, 2026-07-25 — `summary_screen.dart` now computes `hasComparisonData = !(previousExpense == 0 && expense == 0)` and passes it to `SummaryView`, which shows a neutral "Belum ada data untuk dibandingkan, Bun" line (no arrow/color) instead of the misleading "lebih boros" badge when both periods are empty. Also folded into this: replaced "lebih boros" with the neutral "lebih banyak dari sebelumnya" (see PM-05).

### UX-005 — [FIXED] [Medium] [Accessibility]
- Ditemukan: 2026-07-25 07:43 oleh UX Agent
- Screen: Pengaturan > toggle "Mode Gelap"
- Masalah: Switch untuk "Mode Gelap" tidak punya accessible label sama sekali. Dikonfirmasi lewat `adb shell uiautomator dump` (pohon aksesibilitas Android yang sesungguhnya, dipakai TalkBack) — node `android.widget.Switch` di baris ini punya `content-desc=""` (kosong), sementara node lain di layar yang sama (mis. "Kelola Kategori", "Profil", "Generate Data Dummy") semuanya punya content-desc yang jelas. Root cause: `lib/screens/settings_view.dart` baris ~174-187 — `Row([OpenMojiIcon, Text('Mode Gelap'), Switch(value: isDark, onChanged: onToggleDarkMode)])` — teks label "Mode Gelap" cuma sibling Text biasa di sebelah `Switch`, tidak pernah di-attach sebagai semantic label ke Switch-nya (butuh `Semantics(label: 'Mode Gelap', child: Switch(...))` atau `MergeSemantics` yang membungkus Row-nya).
- Kenapa ini masalah (rujuk spec section jika relevan): User TalkBack yang menjelajah Pengaturan akan sampai ke kontrol "Switch, off" tanpa nama sama sekali — tidak tahu ini toggle untuk apa tanpa mencoba mengaktifkannya dan menebak dari efeknya. ini satu-satunya switch/toggle di seluruh app (tidak ada pola serupa lain yang perlu dicek), tapi karena letaknya di baris paling atas & paling gampang dijangkau di Pengaturan, dampaknya cukup terasa untuk fitur aksesibilitas dasar (doc section 8 — non-fungsional — biasanya mencakup aksesibilitas standar).
- Saran perbaikan: Bungkus dengan `Semantics(label: 'Mode Gelap', toggled: isDark, child: Switch(...))`, atau lebih simpel: bungkus seluruh `Row` dengan `MergeSemantics` supaya label "Mode Gelap" otomatis tergabung ke kontrol switch-nya (pola ini juga baik diterapkan preventif ke baris-baris lain yang punya kontrol interaktif + label terpisah, kalau ada).
- Maestro flow: maestro/flows/ux-005-repro.yaml
- Fixed by: Programmer, 2026-07-25 — wrapped the Mode Gelap `Row` in `MergeSemantics` (not a plain `Semantics(label:...)` on the `Switch` alone — that approach was tried first but left the real interactive `Switch` node's `content-desc` empty and instead merged the label into a giant screen-wide node, confirmed via `uiautomator dump`; `MergeSemantics` scopes the merge to just this row). Verified on-device: the `Switch` node now reports `content-desc="Mode Gelap"` and stays a normally-sized, independently tappable node.
